## Сборка: build.zig и кросс-компиляция

### Файл сборки — программа

В Zig сборка описывается файлом `build.zig` на самом Zig. Это не конфигурация, а код с условиями, циклами и функциями:

```
pub fn build(b: *std.Build) void {
    const target = b.standardTargetOptions(.{});
    const optimize = b.option(std.builtin.OptimizeMode, "optimize", "режим") orelse .ReleaseSafe;
    const exe = b.addExecutable(.{
        .name = "clipper",
        .root_source_file = b.path("src/main.zig"),
        .target = target,
        .optimize = optimize,
        .single_threaded = true,
    });
    b.installArtifact(exe);
}
```

`build` не собирает, а описывает граф шагов. Система сборки выполняет только те шаги, чьи входы изменились, и кэширует результаты по содержимому.

### Кросс-компиляция — флаг

`zig build -Dtarget=x86-windows.xp` на машине с Windows 11 собирает 32-битную программу для XP. `-Dtarget=x86_64-linux` — для Linux. Никаких отдельных наборов инструментов: компилятор Zig несёт с собой всё нужное для каждой цели. Это одна из главных причин, по которым язык выбирают для системных программ, даже не собираясь на нём писать: `zig cc` — кросс-компилятор C.

### Шаги-программы

Самое сильное свойство: шаг сборки может быть программой на Zig, собранной под машину сборки.

Пример 1. Компоновщик пишет в заголовок исполняемого файла Windows версию системы 6.0, и XP такой файл не запустит. Клиппер собирает маленькую программу `pe-version` (`.target = b.graph.host`), запускает её на готовом файле и получает исправленную копию. В одном `build.zig` — программы для двух разных систем.

Пример 2. Встроенные книги (эта книга — одна из них) лежат как Markdown в `src/books/`. Программа `tools/books.zig` превращает их в исходник Zig с готовыми строками в windows-1251, а сервер импортирует его как модуль. Пока файлы книг не менялись, шаг не запускается.

### Параметры сборки

```
const lang = b.option(Lang, "lang", "язык интерфейса") orelse .ru;
const options = b.addOptions();
options.addOption(Lang, "lang", lang);
exe.root_module.addOptions("config", options);
```

`zig build -Dlang=en` — параметр приходит в программу как константа модуля `config`, известная при компиляции. Код, который от неё зависит, выбирается `if` при компиляции, и в готовой программе остаётся только нужная ветка. Так в Клиппере выбираются язык интерфейса и то, какие книги встроены.

### `single_threaded` и Windows XP

`.single_threaded = true` сообщает компилятору, что потоков нет. Стандартная библиотека тогда убирает блокировки — а её мьютекс на Windows построен на SRW-блокировках, которых в XP нет. Для Клиппера этот флаг — не оптимизация, а условие запуска на XP.

Официально Zig поддерживает только современные Windows. XP работает потому, что стандартная библиотека позволяет не вызывать того, чего на XP нет, — но никто этого не обещает. Таблицу импорта приходится проверять самому после каждого обновления компилятора.

### Цена

Интерфейс системы сборки меняется чаще, чем сам язык. Файл сборки — первое, что ломается при обновлении компилятора. Это одна из причин, по которым проект закреплён за одной версией.
