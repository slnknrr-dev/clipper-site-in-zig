## Поиск

### Развилка

Посетитель вводит слово. Сайт должен найти книги, стихи, цитаты, в которых оно есть, — в названиях, аннотациях и по возможности в тексте.

### Пути

1. **Просмотр подряд**: пройти по всем записям и проверить вхождение.
2. **Триграммный индекс**: для каждой тройки букв — список документов, где она встречается; запрос пересекает списки.
3. **Инвертированный индекс по словам** с нормализацией (приведение к основе слова, стоп-слова) и ранжированием.
4. **Внешний поисковый движок.**

### Выбор

Путь 1, с ограничением. Названия, аннотации и стихи просматриваются всегда. Полный текст книг просматривается, только пока в снимке не больше 2048 кадров (около 32 МБ текста); дальше поиск по тексту отключается сам. Сравнение — без учёта регистра, побайтово в windows-1251, где перевод в нижний регистр — таблица на 256 значений (страница 0x13).

Почему: для библиотеки одного сообщества просмотр 32 МБ в памяти занимает миллисекунды-десятки миллисекунд и не требует ни одной структуры. Поиск — редкий запрос по сравнению с чтением. Сервер остаётся тупым.

### Тупики

**Поиск по полному тексту без предела.** На большой библиотеке один запрос «а» распакует весь каталог. Это не только медленно, это способ остановить сервер одним адресом. Предел обязателен при любом пути 1.

### Лучше — при других условиях

**Триграммы (путь 2) — при большом каталоге.** Первая версия так и делала: триграмма в windows-1251 — три байта, то есть число меньше 16 777 216, и индекс по ней — арифметика. Поиск находит подстроки, а не только слова, и не требует знать язык. Цена — индекс в снимке размером с заметную долю текста и сложность сборки.

**Инвертированный индекс (путь 3) — когда важна точность.** «Книги» и «книгам» — одно слово для человека и разные для поиска по подстроке. Нормализация решает это, но требует словаря языка и превращает поиск в отдельный продукт. Для библиотеки, где ищут в основном название и автора, это избыточно.

**Фасеты — при каталоге с метаданными.** Первая версия умела «жанр, год и язык сразу». Это превращает поиск в запрос по нескольким индексам сразу — ещё одна ступень ума сервера.

### Цена

Поиск по тексту исчезает при росте библиотеки — тихо, без сообщения посетителю. Это стоило бы показывать. Нет ранжирования: результаты идут в порядке номеров.
