## Цветной вывод и консоль Windows

Цветной вывод — хороший повод поговорить о том, что терминал — не «экран», а программа на другом конце потока байтов, и что Windows отличается от остальных систем сильнее, чем кажется.

### Управляющие последовательности

Цвет в терминале задаётся не вызовом функции, а байтами в том же потоке, что и текст. Последовательность начинается с символа ESC (код 27, `\x1b`), затем `[`, числа и буква:

```
const std = @import("std");

const red = "\x1b[31m";
const green = "\x1b[32m";
const bold = "\x1b[1m";
const reset = "\x1b[0m";

pub fn main() !void {
    const out = std.io.getStdOut().writer();
    try out.print("{s}{s}ошибка:{s} файл не найден\n", .{ bold, red, reset });
    try out.print("{s}готово{s}\n", .{ green, reset });
}
```

`31` — красный текст, `32` — зелёный, `1` — жирный, `0` — сброс. Это стандарт ECMA-48, он старше большинства читателей этой книги.

### Вопрос: а если вывод — не терминал?

Если перенаправить вывод в файл (`программа > log.txt`), в файле окажутся байты `\x1b[31m`. Хорошая программа проверяет, куда пишет:

```
const std = @import("std");

pub fn main() !void {
    const file = std.io.getStdOut();
    const tty = std.io.tty.detectConfig(file);
    const out = file.writer();
    try tty.setColor(out, .red);
    try out.writeAll("ошибка");
    try tty.setColor(out, .reset);
    try out.writeAll("\n");
}
```

`detectConfig` смотрит, терминал ли это, учитывает переменную окружения `NO_COLOR` и систему. На Windows она умеет и старый способ — вызовы консоли, — если управляющие последовательности не поддерживаются.

### Windows: две проблемы, а не одна

**Кодировка.** Консоль Windows по умолчанию ждёт байты в своей кодовой странице (для русской системы — 866 или 1251), а не UTF-8. Строки Zig — UTF-8, и без настройки кириллица выйдет мусором. Клиппер в начале `main` переключает консоль:

```
extern "kernel32" fn SetConsoleOutputCP(cp: c_uint) callconv(.winapi) c_int;

pub fn main() void {
    if (builtin.os.tag == .windows) _ = SetConsoleOutputCP(65001);
    ...
}
```

65001 — номер UTF-8. Обратите внимание, как объявлена функция: `extern "kernel32"` — прямо в коде, без заголовков и без библиотеки C. Компилятор сам знает, как вызвать функцию из системной библиотеки. Это одна из причин, по которым Zig удобен для сборки под Windows без чужого кода.

**Управляющие последовательности.** Консоль Windows понимает их только с Windows 10, и то после явного включения режима `ENABLE_VIRTUAL_TERMINAL_PROCESSING` вызовом `SetConsoleMode`. На Windows XP и 7 их нет вовсе: `\x1b[31m` будет напечатан как есть. Поэтому сервер Клиппера в консоль цвет не пишет: его цель — XP, и «работает везде» здесь важнее красоты.

### Чему учит этот пример

Цветной вывод выглядит как украшение, но за ним — три вопроса, которые возникают в любой системной программе: что на другом конце потока, какую кодировку он ждёт, и какие версии системы надо поддерживать. Zig не прячет ни один из них, и это правильно: язык, который сделал бы «просто цветной print», решил бы за вас, что делать на XP.
