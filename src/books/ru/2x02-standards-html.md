## HTML 4.01: документ, а не приложение

### Что было

HTML 4.01 — рекомендация W3C 1999 года. В ней три варианта:

- **Strict** — без устаревших элементов оформления (`font`, `center`, атрибутов цвета); всё оформление — в стилях;
- **Transitional** — то же плюс устаревшее оформление; так писали почти все;
- **Frameset** — для страниц из фреймов.

XHTML 1.0 (2000) — тот же словарь в синтаксисе XML. В 2003 году его любили объявлять, но почти всегда отдавали как обычный HTML (`text/html`), и браузеры читали его как HTML. Настоящий XHTML (`application/xhtml+xml`) IE6 не понимал вовсе.

### Почему Клиппер выбрал Transitional

Первая строка каждой страницы Клиппера:

```
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN">
```

Transitional — потому что темы повторяют сайты той эпохи, а они оформлялись атрибутами `bgcolor`, `width`, `align` и таблицами. Такая разметка рисуется одинаково везде, включая браузеры, которые стилей не знают. Стили добавляются сверху как улучшение.

Строка `DOCTYPE` — не формальность. С IE6 (и раньше — в IE5 для Mac и Mozilla) браузеры выбирают режим по ней: с полным `DOCTYPE` и адресом DTD — режим стандартов, без него или с неполным — режим совместимости («quirks mode»), где модель блока остаётся старой. Клиппер даёт `DOCTYPE` без адреса DTD — это включает режим совместимости, в котором таблицы и старые атрибуты ведут себя так, как ждали авторы тех лет.

### Таблицы для раскладки

Раскладка таблицами сегодня считается дурным тоном, и для этого есть причины: таблица говорит «здесь табличные данные», а не «здесь колонка меню». Для программ чтения с экрана это плохо.

Но в 2003 году таблица была единственным способом получить колонки, которые одинаково выглядят во всех браузерах. Клиппер берёт её сознательно: все четыре темы — таблицы с колонками, полосами шапки и подвала.

Цена для сервера — ноль. Цена для разметки — немного лишних байтов и семантика, которой нет.

### Что сервер получает от документной модели

Документ HTML 4.01 — законченная вещь. Он не догружает себя, не строит своё содержимое и не меняется после загрузки (кроме мелочей, сделанных скриптом). Отсюда для сервера:

- **страница = ответ на адрес.** Один запрос — один документ. Нет «каркаса», который потом наполняется данными по десяти запросам.
- **ответ можно кэшировать целиком.** Он не зависит от того, что браузер сделает потом.
- **ответ можно проверить целиком.** Тест получает страницу и сравнивает текст. Так устроен контракт Клиппера с макетом: 1200 случаев, каждый — сравнение документов.
- **ответ можно отдать по частям.** Браузер начинает рисовать документ, не дождавшись конца. Сервер может писать по мере готовности.

### Что изменилось бы с современной разметкой

HTML5 добавил семантику (`nav`, `article`), формы с проверкой на клиенте, `canvas`, видео. Почти ничего из этого не меняет сервер: семантические элементы — те же байты. Меняет только то, что переносит логику в браузер: проверка полей на клиенте не отменяет проверки на сервере, а приложение на `canvas` требует от сервера данных, а не документов. Документ остаётся самым дешёвым для сервера видом ответа.
