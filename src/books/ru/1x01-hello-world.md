# Часть I. Первые байты

## Нормальный Hello, World

В большинстве учебников «Hello, World» — одна строка, которая ничему не учит. В Zig она учит сразу трём вещам, и все три понадобятся на сервере.

```
const std = @import("std");

pub fn main() !void {
    const stdout = std.io.getStdOut().writer();
    try stdout.print("Hello, {s}!\n", .{"World"});
}
```

### Вопрос 1. Откуда `std`?

`@import("std")` возвращает значение — структуру, в которой лежит вся стандартная библиотека. Не директива препроцессора, не подключение заголовка, а выражение. В Zig файл — это структура, а импорт — получение этой структуры. Поэтому `std.io` — просто поле.

Следствие: нет «глобального пространства имён». Всё, что вы используете, видно по цепочке полей от импорта. Это ещё не раз окажется важным.

### Вопрос 2. Почему `!void`, а не `void`?

Запись в стандартный вывод может не удаться: вывод закрыт, диск полон, труба оборвана. В большинстве языков `print` такую ошибку проглатывает или бросает исключение, о котором никто не знает. В Zig `print` возвращает возможную ошибку, и её нельзя проигнорировать молча: либо `try` (передать наверх), либо `catch` (обработать). `!void` у `main` означает «main может вернуть ошибку» — тогда программа выйдет с ненулевым кодом и напечатает имя ошибки.

### Вопрос 3. Что такое `.{"World"}`?

Анонимный кортеж. Формат и аргументы проверяются при компиляции: `{s}` требует строку, и если передать число, программа не соберётся. Строка формата не разбирается при запуске вовсе — компилятор превращает её в последовательность вызовов. Это первый пример того, что в Zig называется `comptime`; ему посвящена отдельная глава.

### stdout и stderr

```
std.debug.print("отладка: {d}\n", .{42});
```

`std.debug.print` пишет в stderr и ошибки записи игнорирует. Это для отладки и сообщений о сбоях, а не для данных. Сервер Клиппера печатает в stderr строку о запуске и сообщения об ошибках, а в stdout — только то, что можно перенаправить в файл (например, хеш пароля командой `clipper hash`).

Различие не формальность: если программа пишет и данные, и сообщения в один поток, её вывод нельзя обработать другой программой.

### Буферизация

Каждый вызов `stdout.print` — системный вызов записи. Для одной строки это неважно, для миллиона — решающе.

```
const std = @import("std");

pub fn main() !void {
    var bw = std.io.bufferedWriter(std.io.getStdOut().writer());
    const w = bw.writer();
    for (0..1000) |i| try w.print("{d}\n", .{i});
    try bw.flush();
}
```

Буфер — обычная переменная на стеке: 4 КБ внутри структуры `bw`. Никакого выделения памяти. Но `flush` надо вызвать самому: Zig не делает ничего за спиной, в том числе не сбрасывает буфер при выходе. Забыли `flush` — потеряли конец вывода.

Это первый пример принципа, который проходит через весь язык: **никакого скрытого поведения.** Цена — больше строк. Выигрыш — видно, где происходит запись.

### Что изменилось в 0.15

В 0.15 весь ввод-вывод стандартной библиотеки переписан: буфер переехал внутрь интерфейса записи, `bufferedWriter` и `getStdOut().writer()` уступили место новым вызовам. Код из этой главы на 0.15 не соберётся без правки. Почему так получилось и почему это не ошибка, а стратегия, — в главе о вынужденных решениях.
