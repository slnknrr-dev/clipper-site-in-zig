## Zig 0.14, следующие версии и Windows XP

### Вопрос: почему Клиппер именно на 0.14?

Короткий ответ: 0.14 — это консервация. Это версия, на которой проверено, что программа без библиотеки C собирается под Windows XP и запускается на ней, — и единственная, где это проверено. Любая другая версия означает проверять заново, и каждая следующая версия Zig делает эту проверку дороже.

Длинный ответ — в том, как вообще Zig-программа оказывается на XP.

### Zig не поддерживает XP — и не мешает

Официально Zig поддерживает только современные Windows. Но цель `x86-windows.xp` существует: компилятор знает, что минимальная версия — XP, и умеет собрать для неё код. Дальше всё зависит от того, какие функции системы программа вызывает. Если хоть одна функция появилась позже XP, загрузчик XP откажется запускать программу — не в момент вызова, а сразу, при загрузке.

Значит, задача сводится к одной: ни одна функция в таблице импорта не должна быть новее XP. И вот что нашлось на 0.14.1.

| что | откуда | что сделано |
| версия 6.0 в заголовке PE | компоновщик | после сборки отдельная программа pe-version правит заголовок на 5.1 |
| SRW-блокировки (Vista) | std.Thread.Mutex | сборка с .single_threaded = true |
| RtlGetSystemTimePrecise (Windows 8) | std.time на Windows | своё время через GetSystemTimeAsFileTime в src/sys.zig |
| то же время | клиент TLS стандартной библиотеки | в сборке для XP исходящего https нет вовсе |
| отображение файла в память | в std нет для Windows | свои объявления CreateFileMapping и MapViewOfFile |
| двойной стек IPv6 | нет в XP | сервер молча слушает только IPv4 |

Каждая строка — место, где стандартная библиотека Zig (или компоновщик) тянет программу к новой Windows, а проект её отводит. Это не борьба с языком: Zig позволяет не вызывать функцию стандартной библиотеки и объявить системную функцию самому одной строкой `extern "kernel32"`. Но это постоянная работа, и её результат верен только для той версии стандартной библиотеки, на которой его проверили.

### Что меняется в следующих версиях

Здесь нужна оговорка: эта глава не проверяла 0.15 и 0.16 на XP. Сказанное ниже — о направлении, а не о конкретных функциях.

- **0.15 переписал ввод-вывод.** Новые интерфейсы чтения и записи заменили старые; код, который читает и пишет через стандартную библиотеку, надо переписывать. Каждый переписанный путь — новые вызовы системы, которые надо заново проверить по таблице импорта.
- **Дальше — новая модель ввода-вывода.** По заметкам к выпускам, переписывание готовит возврат асинхронности через общий интерфейс ввода-вывода. Чем больше стандартная библиотека делает за программу, тем больше системных функций она выбирает сама — и тем больше шансов, что среди них окажется функция новее XP.
- **Собственные бэкенды и компоновщик.** Код запуска программы и компоновка меняются вместе с ними. Правка заголовка PE на 0.14 нужна из-за поведения компоновщика 0.14; у нового компоновщика поведение может быть другим — лучше или хуже для XP.

Общее направление понятно: Zig движется к удобной стандартной библиотеке для современных систем. Это правильно для языка и неудобно для XP. Каждая версия делает XP не невозможной, а дороже.

### «Сделан иначе»

Здесь важно понять главное: Zig 0.15 — это во многом другой язык для того, кто пишет серверы, хотя синтаксис почти тот же. Изменились:

- интерфейсы чтения и записи (то, через что проходит каждый байт сервера);
- контейнеры по умолчанию (`ArrayList` без распределителя внутри);
- то, что считается правильным способом ждать ввода-вывода.

Код Клиппера переживёт переход в тех местах, где он работает со срезами байтов: разбор HTTP, формат снимка, шаблоны, журнал. И не переживёт без переписывания там, где он трогает систему и стандартный ввод-вывод: `src/sys.zig`, `src/net/`, сжатие кадров, выгрузки, разбор архивов. Это не случайность: зависимость от стандартной библиотеки нарочно собрана в немногих файлах.

### Что выбрать для своего проекта

Если цель — современные системы, берите свежую версию Zig и обновляйтесь вместе с языком: так долг не копится.

Если цель — старые системы (XP, Windows 7, старое железо), закрепите версию, на которой это проверено, держите компилятор в папке проекта и обновляйтесь только тогда, когда готовы заново проверить таблицу импорта и запустить программу на настоящей старой системе. Клиппер выбрал второе. Цена — отстающий язык и растущий долг. Выигрыш — один исполняемый файл, который работает от XP до Windows 11.

Последнее честное замечание: на настоящей Windows XP Клиппер пока не запускался. Проверены сборка, заголовок PE и таблица импорта, а 32-битная сборка запущена на Windows 11. Консервация сделана; проверка на живой XP — следующий шаг.
