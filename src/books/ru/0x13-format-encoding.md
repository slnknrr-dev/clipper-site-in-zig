# Часть V. Граница с внешним миром

## Страницы 2003 года и windows-1251

### Развилка

Что именно сервер отдаёт браузеру и в какой кодировке хранит текст.

### Пути для разметки

1. Современный фронтенд: скрипты строят страницу в браузере, сервер отдаёт данные.
2. Серверная разметка с современным CSS и скриптами для удобства.
3. HTML 4.01, таблицы, CSS второго уровня, скрипты только там, где без них неудобно, — как в 2003 году.

### Выбор

Путь 3. Страница без скриптов зависит только от адреса — значит, её можно собрать один раз и отдавать всем (это то, что делает возможным кэш гостевых страниц). Она весит 5–30 КБ и открывается в любом браузере на любом устройстве. Она ставит потолок сложности: если функцию нельзя сделать формой и ссылкой, её, скорее всего, не нужно делать.

Единственный скрипт — своё контекстное меню на странице чтения для цитат и закладок (`oncontextmenu`, работает с Internet Explorer 5). Под текстом есть форма, которая делает то же без скрипта.

**Тупик:** путь 1 при требовании тупого сервера. Он переносит работу в браузер, но не убирает её с сервера: сервер всё равно отдаёт данные, проверяет права и хранит записи, а вдобавок обслуживает интерфейс программирования. И страница без скриптов перестаёт работать вовсе.

### Пути для кодировки

1. **UTF-8 везде.**
2. **windows-1251 для страниц и данных, UTF-8 на границах** (файлы книг, выгрузки, JSON).
3. **UTF-16 внутри** (как в Windows и Java).

### Выбор

Путь 2. Кириллическая буква в UTF-8 — два байта, в windows-1251 — один. Для русского текста это почти вдвое меньше памяти, трафика и размера снимка. Но главный выигрыш — простота: один байт — один знак.

- Перевод в нижний регистр — таблица на 256 значений.
- Поиск без учёта регистра — цикл по байтам.
- Строку можно обрезать в любом месте, не разрезав знак пополам.
- Триграмма — три байта, то есть число.

Знаки вне кодировки в разметке пишутся как `&#N;` — это законный HTML 4. Строки исходников перекодируются при компиляции, так что в программе нет ни одной перекодировки текста интерфейса на запросе.

### Тупик, найденный на деле

Механизм выбора языка (`-Dlang`) сначала знал грузинский. Проверка показала, к чему это ведёт: в разметке грузинские буквы прошли бы как `&#N;`, но в данных — заголовках, именах, тексте книг — превратились бы в вопросительные знаки, а сборщик встроенных книг такой текст не принял бы. Чтобы грузинская версия стала настоящей, пришлось бы переводить на UTF-8 страницы, формы, поиск и формат снимка. Грузинский из сборки вырезан: `-Dlang=ka` — ошибка, а не тихо испорченный сайт.

Английский язык в windows-1251 помещается целиком, поэтому английская сборка (`-Dlang=en`) — настоящая: интерфейс из каталога `src/t9n/en.t9n` и английские встроенные книги. Страницы при этом остаются в windows-1251.

Это хороший пример того, как решение, принятое ради скорости русского текста, через год определяет, на каких языках сайт вообще может существовать.

### Лучше — при других условиях

**UTF-8 — для многоязычной библиотеки.** Если сайт должен держать книги на любых языках, путь 1 — единственный честный. Цена: регистр — по таблицам Юникода, обрезка строки — с проверкой границ знака, поиск без учёта регистра — нетривиален (немецкая «острая s», турецкая «i» с точкой и без), размер русского текста почти вдвое больше. Сжатие кадров съедает часть разницы, но не всю.

**Смешанная схема.** Хранить UTF-8, а для русских страниц перекодировать на отдаче. Получаются недостатки обоих путей: и размер, и работа на запросе. Тупик.

### Цена

Формы: браузер присылает текст в кодировке страницы, знаки вне неё приходят как `&#N;` или теряются. Адреса, набранные руками, приходят в UTF-8, и сервер обязан это распознать (`cp.looksUtf8` существует только из-за этого решения). Встроенные книги собираются только из текста, помещающегося в windows-1251.
