# Часть VII. Язык и итоги

## Почему Zig и почему 0.14

Язык выбирался под задачу, а не наоборот. Задача: программа отдаёт ядру указатели на байты, которые уже лежат в памяти, не выделяя ничего по дороге; она же разбирает враждебные файлы; она же собирается под систему двадцатилетней давности без единой внешней библиотеки. Подробный разбор языка, его устройства и причин, по которым он такой, — в книге 1, «Zig для backend». Здесь — только развилка.

### Пути

| что нужно | C | C++ | Rust | Zig |
| проверка границ в боевой сборке | нет | частично | да | да |
| вычисления при компиляции на том же языке | нет | своим подъязыком | ограниченно, плюс макросы | да |
| нет скрытых выделений и вызовов | да | нет | почти | да |
| гарантии владения при компиляции | нет | нет | да | нет |
| кросс-сборка из коробки | нет | нет | частично | да |
| стабильность языка | да | да | да | нет |

Языки со сборкой мусора (Go, Java, C#) — тупик до сравнения: «ноль выделений на запрос» пришлось бы отвоёвывать у среды исполнения.

**C** — проверки границ ручные, для шаблонов нужен второй язык-генератор, а рамка требует обходиться без библиотеки C, что отнимает половину смысла писать на C.

**C++** — возможностей хватает, но их слишком много: строка `a = b` может выделять память, бросать исключение и вызывать пользовательский код. Для программы, главное свойство которой — «на пути запроса ничего не выделяется», нужно, чтобы это свойство проверялось чтением кода.

**Rust** — самый сильный соперник. Его гарантии владения настоящие и ловят при компиляции то, что Zig ловит при выполнении или не ловит вовсе. Против него здесь сработали три вещи: самое ценное место программы — срезы внутри отображённого файла и буферы, живущие дольше запроса, — как раз то, где Rust требует `unsafe`; экосистема построена на пакетах, а рамка их запрещает; Windows XP стандартной библиотекой Rust давно не поддерживается.

### Лучше — при других условиях

Для команды в двадцать человек и кода, который проживёт десять лет, лучше Rust: гарантии владения окупают цену обучения. Для сервиса с базой данных и обычными требованиями лучше Go: он быстрее в разработке, а сборка мусора там не помеха. Zig выигрывает именно в этой рамке: один автор, тупой сервер, никаких зависимостей, древние цели.

### Почему версия закреплена

Проект собирается только Zig 0.14.x: `build.zig` отказывается работать на другой версии. Причин четыре: закрепление дешевле поддержки нескольких версий; в 0.15 полностью переписан ввод-вывод стандартной библиотеки; по заметкам к выпуску в переписанном модуле deflate осталась только распаковка, а Клиппер сжимает каталог именно им; сборка под XP проверена на 0.14.1 и на другой версии потребует новой проверки. Две средние причины описывают чужой код, который меняется, — перед обновлением их стоит сверить с заметками к выпуску.

Закрепление — долг, и он растёт. Поэтому всё, что сильнее всего зависит от стандартной библиотеки, собрано в немногих местах: `src/sys.zig`, `src/net/net.zig`, вызовы сжатия в `src/snapshot.zig` и `src/import/common.zig`. Остальной код работает со срезами байтов. Зависимость, которую нельзя убрать, надо хотя бы собрать в одном месте.
