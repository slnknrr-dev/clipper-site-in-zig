## Целые числа: ширина, знак и переполнение

### Вопрос: зачем `u3`?

В Zig целое может быть любой ширины от 0 до 65535 бит: `u3`, `i7`, `u24`, `u128`. Это кажется странностью, пока не понадобится. В Клиппере функции сайта хранятся перечислением с типом-основой `u4` — двенадцать значений помещаются в четыре бита, и компилятор не даст присвоить пятнадцать. Права участника — `u8`, где каждый бит — право. Ширина типа — это документация, которую проверяет компилятор.

### Переполнение — ошибка, а не поведение

```
const std = @import("std");

pub fn main() void {
    var a: u8 = 250;
    a += 10; // в Debug и ReleaseSafe — остановка: integer overflow
    std.debug.print("{d}\n", .{a});
}
```

В C переполнение беззнакового — заворачивание по модулю, знакового — неопределённое поведение, на которое оптимизатор вправе опираться как угодно. В Zig переполнение обычной операцией — ошибка. В сборках Debug и ReleaseSafe она останавливает программу с указанием места; в ReleaseFast и ReleaseSmall проверка убрана, и поведение не определено.

Если заворачивание нужно, его пишут явно:

- `a + b` — переполнение — ошибка;
- `a +% b` — по модулю 2^N;
- `a +| b` — с насыщением: не больше максимума и не меньше минимума;
- `@addWithOverflow(a, b)` — пара: результат и бит переполнения.

То же для `-`, `*` и сдвигов. Каждое вычитание беззнаковых — место, где надо решить, что должно произойти, и записать решение значком. В Клиппере так написан разбор заголовка `Range`: `len -| n` — если просят больше, чем есть, получается ноль, а не огромное число.

### Почему это важно для сервера

Ошибка, которую Клиппер нашёл тестом со случайным вводом, была именно такой: запрос последних пяти байтов пустого файла давал вычисление «ноль минус один». В ReleaseSafe сервер остановился. В C та же ошибка дала бы длину в 18 квинтиллионов и чтение чужой памяти. Проверка превратила уязвимость в отказ — громкий и с адресом.

Поэтому Клиппер по умолчанию собирается ReleaseSafe: быстрый код с проверками. ReleaseFast быстрее на проценты и опаснее на порядки.

### Приведения — только явные

```
const big: u32 = 300;
const small: u8 = @intCast(big);   // проверка: 300 не влезает — остановка
const low: u8 = @truncate(big);    // обрезка старших битов: 44
const f: f64 = @floatFromInt(big);
```

Неявно Zig расширяет только туда, где значение точно помещается: `u8` в `u32` — можно, обратно — нет. Каждое сужение видно в коде и называется по смыслу: «проверь, что влезает» или «отрежь».

### `usize` и `comptime_int`

`usize` — целое шириной с указатель; это тип длин и индексов. Литерал `300` сам по себе имеет тип `comptime_int` — целое произвольной точности, существующее только при компиляции. Поэтому `const x = 1 << 100;` — законно, пока `x` не попытались положить в переменную реального типа.

### Цена

Явность многословна. Арифметика со смешанными типами требует приведений, и первые дни это раздражает. Взамен вы получаете язык, где из текста видно, где может быть переполнение, — и где его быть не может.
