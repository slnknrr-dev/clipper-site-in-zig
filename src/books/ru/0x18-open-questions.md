## Что не сделано и не проверено

Исследование кончается картой мест, где сказанное перестаёт быть доказанным.

### Не проверено

- **Linux в работе.** Сборка под Linux проходит (`zig build -Dtarget=x86_64-linux`), но в целевые сборки не входит; сетевой зонд, замеры и гонки процессов шли только на Windows 11.
- **Настоящая Windows XP.** Сборки для XP (32 и 64 бита) помечены для Windows 5.1, таблица импорта проверена, обе запущены на Windows 11. На самой XP сервер не запускался.
- **Скриншоты главных по сочетаниям разделов.** Тест-обход проверяет ссылки и тексты всех сочетаний во всех темах, но сравнить вид с оригиналами тем можно только глазами.
- **Сбой посреди записи в B+ дерево** — устойчивость по построению, теста нет.
- **Полное рукопожатие TLS в памяти** — есть сверка ключей с эталоном и работа с curl и openssl; стороннего аудита нет.
- **Чужие файлы книг.** PDF — из двух браузеров, EPUB — собственная выгрузка, DjVu — две книги без оглавления.
- **Федерация по https** между двумя сайтами.
- **Кэш кадров против более простого** — выбор по статье, не по замеру.
- **Нагрузка из сети** — клиент замера работал на той же машине.

### Не сделано

- Уплотнение журнала: файл только растёт.
- Возврат места в B+ дереве без перезапуска.
- Разбор книг и вопрос соседу вне цикла событий.
- Флаг «скрыто» для сообщений (минимальная модерация, страница 0x12).
- Предупреждение посетителю, что поиск по тексту отключён из-за размера библиотеки.
- Разные типы для сырой и экранированной строки.
- zstd по умолчанию: снимок по-прежнему сжимается deflate, zstd со словарём из файла — только по флагу `-zstd`; словарь не переобучается сам, когда библиотека растёт.

### Как повторить

```
git clone https://github.com/slnknrr-dev/clipper-site-in-zig
cd clipper-site-in-zig
zig build
zig-out/bin/clipper -p 3000 -pwd ПАРОЛЬ
```

Сайт откроется на `http://localhost:3000/`, эта книга — на `/b/0`. Войти в `/u/0` можно с этой же машины логином admin и паролем из флага.

| команда | что получится |
| zig build | целевые сборки в .build (nt-i686-en-all, nt-x86_64-en-nobook, nt51-i686-ru-all, nt51-x86_64-ru-all, linux-x86_64-en-all) и сервер для этой машины в zig-out/bin |
| zig build -Dlang=en | интерфейс и книги на английском |
| clipper -p 3000 -Nbdfq | песенник: только стихи и песни |
| zig build -Dbook0=false | без этой книги: /b/0 отвечает 404 |
| zig build -Dbooks=true | с книгами /b/1 (о Zig) и /b/2 (о вебе) |
| clipper zstd 16 | словарь clipper16.zstd из текстов своей библиотеки |
| clipper -p 3000 -zstd | кадры каталога сжаты своим zstd со словарём из файла |
| zig build -Dzstd=false | без zstd: нет ни флага -zstd, ни команды clipper zstd |
| clipper -p 3000 -pdf -djvu | загрузка PDF и DjVu (экспериментально) |
| zig build -Dpdf=false -Ddjvu=false | без разбора PDF и DjVu |
| zig build test | модульные тесты и враждебный ввод |

## Вместо послесловия

Если из всей книги оставить один абзац, он был бы таким. Разделите данные на те, что читают, и те, что пишут. Первые подготовьте заранее и не трогайте. Вторые записывайте самым простым способом, который переживает сбой. Не делайте на запросе того, что можно сделать до него. И у каждой возможности сайта спросите, на какую ступень она поднимает сервер, — прежде чем её добавить.

Библиотека, которой посвящён этот проект, держалась на плаву не благодаря технологиям. Она держалась на людях и на нескольких простых решениях, принятых вовремя: короткий адрес, открытые данные, много дверей. Клиппер — попытка отнестись к этим решениям всерьёз и посмотреть, как далеко можно уйти с одним исполняемым файлом.

Корабль на логотипе идёт быстро. Но главное в корабле — что он держится на воде.
