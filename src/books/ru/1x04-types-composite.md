## Массивы, срезы, указатели и структуры

### Пять видов указателя

В C указатель один, и по типу `char *` нельзя понять, на что он показывает: на один символ, на массив, на строку с нулём в конце. В Zig это разные типы.

| тип | что это |
| *T | указатель на одно значение |
| [*]T | указатель на неизвестное число значений (как в C) |
| []T | срез: указатель и длина |
| [*:0]T | указатель на последовательность, кончающуюся нулём |
| [:0]T | срез, за которым гарантированно стоит ноль |
| ?*T | указатель, который может быть null |

Обычный указатель `*T` не может быть null. Чтобы он мог, тип пишется `?*T`, и перед использованием его надо проверить. Это целый класс ошибок, убранный типом.

### Срез — главный тип в серверном коде

Срез — пара «указатель, длина». Он не владеет памятью, а показывает на неё. Почти весь Клиппер работает со срезами: разбор запроса возвращает срезы в буфер сокета, поиск книги возвращает срез в отображённый файл, страница пишется срезами.

```
const std = @import("std");

pub fn main() void {
    const req = "GET /b/42 HTTP/1.1";
    const sp = std.mem.indexOfScalar(u8, req, ' ').?;
    const path = req[sp + 1 .. sp + 6];
    std.debug.print("{s}\n", .{path}); // /b/42
}
```

`path` — не копия, а окно в `req`. В отладочной сборке выход за границу среза — остановка. Цена: срез живёт не дольше памяти, на которую показывает, и язык за этим не следит. Об этом — глава о памяти.

### Вопрос: что такое строковый литерал?

Тип `"Hello"` — `*const [5:0]u8`: указатель на массив из пяти байтов, за которым стоит ноль. Он неявно превращается в `[]const u8` (срез) и в `[*:0]const u8` (строку C). Отдельного типа «строка» в Zig нет. Строка — это байты.

Почему так: потому что «строка» в каждом языке — это решение о кодировке, владении памятью и неизменяемости, принятое за вас. Zig отказывается принимать его за вас. В Клиппере это особенно заметно: строки внутри сервера — в windows-1251, а не в UTF-8, и тип `[]const u8` ничего не мешает.

### Опциональные значения и объединения

`?T` — значение или `null`. Разворачивается `if (x) |v|`, `orelse` или `.?` (последнее — «я уверен, что не null», с проверкой в Debug).

`union(enum)` — размеченное объединение: значение одного из вариантов плюс метка, каким. `switch` по нему обязан разобрать все варианты. В Клиппере так устроено хранилище записей: `union(Kind) { journal: Journal, btree: Tree }`. Добавь третий вариант — компилятор покажет все места, где его забыли.

### Структуры и раскладка в памяти

У обычной `struct` порядок полей в памяти не определён: компилятор вправе переставить их ради выравнивания. Это хорошо для памяти и плохо для файлов. Для данных, которые лежат в файле или передаются системе, есть два других вида:

- `extern struct` — раскладка по правилам C: поля по порядку, понятное выравнивание. Такие структуры Клиппер кладёт в файл снимка и читает прямо из отображённой памяти.
- `packed struct` — поля вплотную, побитово; удобно для флагов и сетевых заголовков.

```
const Page = extern struct {
    first_frame: u32,
    n_frames: u32,
    len: u32,
};
comptime {
    std.debug.assert(@sizeOf(Page) == 12);
}
```

Последние три строки — проверка при компиляции. Если кто-то добавит поле и изменит размер, программа не соберётся. Встроенные функции `@sizeOf`, `@offsetOf`, `@alignOf` превращают раскладку из догадки в утверждение.

### Цена

Пять видов указателя надо выучить, и первые недели приведение среза к указателю на строку C кажется бюрократией. Взамен тип говорит, что лежит по адресу, — а в C это приходится выяснять, читая код вызывающего.
