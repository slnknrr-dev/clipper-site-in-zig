## Права, модерация и чего в Клиппере нет

### Что есть

У участника шесть прав: форум, комментарии, черновики, цитаты, выкладывание книг и отметка «сотрудник» (у сотрудника свой набор разрешённых форматов загрузки). Права хранятся одним байтом в учётной записи; проверка — одна операция «и». Участника можно заблокировать. Двенадцать переключателей в панели выключают части сайта целиком.

Над этим — флаги запуска `-M`, `-R`, `-G` и `-N` (страница 0x16): для каждого из пяти разделов — пишут все, пишут только модераторы, только чтение, открыто ли гостям, есть ли раздел вообще. Модератор здесь — участник с правом «сотрудник». Правила раздела — пять битов на каждый вид ограничения, и проверка на запросе — те же операции «и»: решение «кто что может» стало чуть шире, но не стало машиной состояний.

Сайтом управляет встроенный администратор `/u/0`, но не так, как обычно. Его вход задаётся флагами запуска (`-l`, `-pwd`, `-phc`) и действует только с этой же машины. Это не способ управлять сайтом, а способ его настроить: войти локально, завести участника и дать ему права. Без пароля в флагах в `/u/0` не войти вовсе.

### Почему так

Встроенный администратор с паролем в базе — классическая дыра: пароль по умолчанию, перебор, утечка базы. Ограничение «только с этой машины» убирает его из поверхности атаки: снаружи `/u/0` — просто страница. А задание пароля флагом, а не файлом настроек, делает администратора явным: если сервер запущен без пароля, его нет.

Почему всего шесть прав, а не роли. В устройстве с ролями есть вопрос «кто может выдавать роль, выдающую роли», и на него нужно отвечать кодом. Шесть независимых битов отвечают на всё, что нужно сообществу в несколько тысяч человек.

### Чего нет — и почему это решение

Нет премодерации, жалоб, скрытия отдельных сообщений, журнала действий модераторов. Права по разделам есть только в грубом виде — «пишут только модераторы» на весь раздел, без прав на отдельный форум или тему. Как показала ось (страница 0x05), каждая из этих вещей поднимает сервер на ступень: машина состояний сообщения, решение «кто что видит» на каждом показе, вторичные индексы для очередей, поломанный кэш.

### Пути, если модерация понадобится

1. **Удаление вместо скрытия.** Модератор удаляет сообщение; ничего не надо показывать выборочно. Самый тупой путь, и для маленького сообщества часто достаточный. Цена — нельзя отменить.
2. **Флаг «скрыто» без исключений.** Скрытое не видит никто, кроме `/u/0`. Кэш не ломается: для гостей страница одна. Нужен один бит в значении и одна проверка при показе.
3. **Полная модель**: состояния, исключение для автора, очередь, журнал. Ломает кэш, требует индексов.

**Лучшее для Клиппера** — путь 2. Он даёт обратимость и сохраняет главное свойство: гостевая страница одна для всех. Путь 3 стоит брать только тогда, когда сообщество выросло настолько, что модераторов несколько и им нужно видеть работу друг друга.

### Анонимные доски — модерация временем

Доски с автоудалением нити через час, шесть часов или сутки — тоже модерация, только самая тупая из возможных: всё исчезает само. Это не случайное совпадение. Разговор, который не останется, не нужно модерировать так же тщательно, как архив. Цена переложена на время, и сервер за это платит только проверкой срока при показе и редкой чисткой.
