## Тесты

### Тесты рядом с кодом

```
fn add(a: u32, b: u32) u32 {
    return a + b;
}

test "сложение" {
    try std.testing.expectEqual(@as(u32, 5), add(2, 3));
}
```

Тест — блок в том же файле, что и код. `zig test файл.zig` собирает и запускает все тесты файла; в обычной сборке их нет. Название — строка, на любом языке.

Почему рядом: тест — пример использования, и ему место рядом с тем, что он показывает. И тест видит закрытые функции файла.

### Ловушка: тесты, которые не запускаются

Тесты файла попадают в прогон, только если файл «достижим» из корня. Импорт файла не делает его тесты достижимыми, если на них никто не ссылается. Поэтому в Клиппере есть `src/lib.zig`, единственная задача которого — перечислить все модули:

```
test {
    inline for (.{ cp1251, out, http, journal, btree, ... }) |m| _ = m;
}
```

Забыть добавить модуль в этот список — получить тесты, которые никогда не запускаются и всегда «проходят». Это настоящая ловушка языка, и о ней надо знать заранее.

### Распределитель, который считает

`std.testing.allocator` запоминает каждое выделение. Если к концу теста что-то не освобождено, тест падает и показывает, где это выделено. Если освободили дважды — тоже. Каждый тест, работающий с памятью, — заодно тест на утечки.

### Случайный ввод с постоянным зерном

```
var prng = std.Random.DefaultPrng.init(42);
const rnd = prng.random();
```

Генератор с постоянным зерном даёт одну и ту же последовательность при каждом запуске. Упавший случай повторяется, и его можно отладить. Случайный тест, который падает раз в неделю и не повторяется, хуже отсутствия теста: он приучает не верить красному.

### Режим сборки тестов

Тесты Клиппера собираются в Debug — со всеми проверками. Проверка границ и переполнения превращает любую ошибку разборщика в немедленную остановку с адресом. Тесты враждебного ввода без этих проверок ловили бы только падения, а с ними — и тихие выходы за границу.

### Чего тесты Zig не умеют

Нет встроенных моков, фикстур, параметризованных тестов. Есть только блок `test` и функции проверки. Всё остальное — обычный код. Это последовательно: язык не добавляет механизм, если его можно написать функцией.
