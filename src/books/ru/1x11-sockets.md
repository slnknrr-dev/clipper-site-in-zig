## Сокеты и цикл событий

### Простейший сервер

```
const std = @import("std");

pub fn main() !void {
    const addr = try std.net.Address.parseIp("127.0.0.1", 3000);
    var server = try addr.listen(.{ .reuse_address = true });
    defer server.deinit();
    while (true) {
        const conn = try server.accept();
        defer conn.stream.close();
        try conn.stream.writeAll("HTTP/1.1 200 OK\r\nContent-Length: 6\r\n\r\nПри");
    }
}
```

Это работает и учит тому, что HTTP — просто байты в сокете. Но такой сервер обслуживает одно соединение за раз: пока медленный клиент читает ответ, остальные ждут.

### Неблокирующие сокеты и готовность

Цикл событий переворачивает модель. Сокеты переводятся в неблокирующий режим: чтение, когда данных нет, не ждёт, а сразу возвращает ошибку `WouldBlock`. А система сообщает, какие сокеты готовы:

- `select` — старейший способ, есть везде, включая Windows XP; перебирает все сокеты на каждом вызове;
- `poll` — то же без ограничения на номер сокета;
- `epoll` (Linux) — регистрируешь сокет один раз, система возвращает только готовые;
- IOCP (Windows) — модель «операция завершена», а не «сокет готов»;
- `io_uring` (новый Linux) — очередь операций в общей с ядром памяти.

Цикл: спросить систему, что готово; для каждого готового — прочитать, что пришло, или дописать, что не ушло; повторить. Всё в одном потоке.

### Как выбрать реализацию при компиляции

```
const builtin = @import("builtin");
pub const is_windows = builtin.os.tag == .windows;
pub const Socket = if (is_windows) std.os.windows.ws2_32.SOCKET else std.posix.socket_t;
pub const Poller = if (is_windows) SelectPoller else EpollPoller;
```

`builtin.os.tag` известен при компиляции, и `if` по нему выбирает тип. Невыбранная ветка не компилируется вовсе — в ней можно обращаться к функциям, которых на этой системе нет. Препроцессора нет, и он не нужен: условная компиляция — обычное выражение.

У обоих опросчиков одни методы: `init`, `add`, `modify`, `remove`, `wait`. Интерфейс нигде не объявлен — договор проверяется тем, что цикл сервера собирается под обе системы. Это утиная типизация при компиляции. Цена: правка на одной системе может сломать другую, и узнать это можно, только собрав под другую.

### Ответ без копирования

Готовый ответ — несколько кусков памяти: заголовок, тело из кэша, тело из отображённого файла. Системный вызов `sendmsg` (Linux) или `WSASend` (Windows) принимает список кусков и отправляет их одним вызовом. Копировать в один буфер не нужно.

### Особенности Winsock, найденные на деле

Сокет, унаследованный дочерним процессом, на Windows снова блокирующий: признак «неблокирующий» живёт в памяти процесса. А неблокирующий `accept` в нескольких процессах на одном сокете может оставить один из них ждать внутри вызова. Обе вещи — не из документации, а из зависшего сервера. Подробнее — книга 0, страница о цикле событий.

### Почему не `std.http.Server`

В стандартной библиотеке есть сервер HTTP. Он работает поверх блокирующего соединения и рассчитан на модель «поток на соединение» или на простые случаи. Для цикла событий нужен разборщик, который принимает байты кусками и умеет сказать «пока не хватает». Это следующая глава.
