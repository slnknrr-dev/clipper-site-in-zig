## HTTP руками

### Вопрос: зачем писать разбор HTTP самому?

Потому что в цикле событий байты приходят кусками. Разборщику надо уметь сказать три вещи: «запрос целиком, вот он», «пока не хватает, жди ещё», «это не HTTP, закрывай». И делать это без выделения памяти: всё, что он возвращает, — срезы в буфер соединения.

### Тип результата

```
pub const Parsed = union(enum) {
    ok: Request,
    incomplete,
    fail: u16, // код ответа: 400, 405, 411, 431, 501, 505
};
```

Объединение с меткой — естественный тип для разбора: три разных исхода с разными данными, и `switch` обязан разобрать все. Ошибка здесь — не `error`, а вариант с кодом ответа: это ожидаемый исход, который превращается в ответ клиенту, а не исключительная ситуация.

### Строгость

Разбор в Клиппере строгий: строки разделены только `\r\n`, заголовок не длиннее 8 КБ, нет `Host` — 400, `Transfer-Encoding: chunked` в запросе — 501, у POST нет длины — 411. Строгость — защита: каждый допуск («а примем и `\n` без `\r`») — место, где два разборщика по-разному поймут один запрос, а это класс атак на прокси.

### Срезы вместо копий

`Request` — набор срезов: метод, путь, строка параметров, значения нужных заголовков. Все они показывают в буфер соединения. Пока запрос обрабатывается, буфер не трогают; после ответа — переиспользуют. Никаких строк в куче.

Параметры адреса и формы декодируются (`%41` -> `A`) в арену запроса — единственное место, где нужно копирование, потому что раскодированная строка короче исходной и не совпадает с ней байт в байт.

### Проверка на враждебном вводе

Разборщик — функция «байты -> результат», без сокетов. Поэтому его можно кормить случайными и испорченными байтами миллионами:

```
test "случайный ввод не роняет разбор" {
    var prng = std.Random.DefaultPrng.init(42);
    const rnd = prng.random();
    var buf: [512]u8 = undefined;
    for (0..60_000) |_| {
        const n = rnd.uintLessThan(usize, buf.len);
        rnd.bytes(buf[0..n]);
        _ = parse(buf[0..n]); // не должно быть ни паники, ни выхода за границы
    }
}
```

Зерно постоянное — упавший случай повторяется при каждом запуске. Тест собран в Debug, где включены проверки границ и переполнения: любая ошибка разбора становится остановкой с адресом, а не тихой порчей.

### Цена

Свой разбор HTTP — это ответственность за каждый угол спецификации. Клиппер поддерживает HTTP/1.0 и 1.1 и честно отказывает во всём остальном (HTTP/2 — 505). Для сервера за прокси этого достаточно; для сервера, который должен говорить со всем миром напрямую, — нет.
