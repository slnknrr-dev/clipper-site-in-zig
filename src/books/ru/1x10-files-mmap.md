## Файлы, отображение в память, блокировки

### Файлы и каталоги

```
const std = @import("std");

pub fn main() !void {
    var dir = try std.fs.cwd().makeOpenPath("data", .{});
    defer dir.close();
    try dir.writeFile(.{ .sub_path = "hello.txt", .data = "привет\n" });
    var buf: [64]u8 = undefined;
    const got = try dir.readFile("hello.txt", &buf);
    std.debug.print("{s}", .{got});
}
```

Всё через каталог (`Dir`): открыли каталог — открываем файлы относительно него. Это не прихоть. Пути относительно открытого каталога безопаснее (каталог не подменить между проверкой и открытием) и одинаковы на всех системах. В Клиппере вся папка библиотеки открывается один раз при старте, и дальше сервер работает только внутри неё.

`readFile` в готовый буфер не выделяет память; `readFileAlloc(a, путь, предел)` выделяет, и предел обязателен — файл не может съесть всю память.

### Атомарная замена файла

Записать новый файл целиком так, чтобы сбой не оставил полузаписанного, — классическая задача. Решение: записать во временный файл и переименовать. Клиппер переключает снимок каталога так:

```
try root.writeFile(.{ .sub_path = "library.current.tmp", .data = file_name });
try root.rename("library.current.tmp", "library.current");
```

Переименование в пределах одного каталога атомарно и на Linux, и на Windows: читатель видит либо старый указатель, либо новый.

### Отображение в память

Отображение (`mmap` на Linux, `CreateFileMapping` и `MapViewOfFile` на Windows) делает файл частью адресного пространства: чтение памяти — чтение файла, а подгружает страницы сама система. Для неизменяемого файла это лучший способ чтения: нет копирования в буфер, нет кэша в программе, несколько процессов делят одну физическую память.

В стандартной библиотеке есть `std.posix.mmap`, но для Windows отображения нет. Клиппер пишет его в `src/sys.zig` — двадцать строк с объявлениями `extern "kernel32"`. Это типичная ситуация: стандартная библиотека Zig ориентирована на POSIX, и для Windows часть системных вещей приходится объявлять самому. Язык делает это лёгким: объявление функции из системной библиотеки — одна строка.

Отображённая память — чужие байты. Файл могли испортить. Правило: при открытии проверить все смещения и длины, которые будут использованы как индексы, — и дальше доверять. Проверять при каждом обращении — честнее, но тогда чтение перестаёт быть бесплатным.

### Блокировка файла

Несколько процессов пишут в один журнал. Нужна блокировка, видная всем процессам. В Zig 0.14 у `File` есть `lock`, но Клиппер использует свою в `src/sys.zig`: `flock` на Linux, `LockFileEx` на Windows. Причина — XP: нужно точно знать, какие функции системы вызываются.

Блокировка файла — единственный примитив синхронизации, который нужен серверу из нескольких процессов. Ни мьютексов в памяти, ни атомарных переменных: процессы общаются через файл и блокировку на нём.

### Цена

Различия систем никуда не деваются: их надо собрать в одном файле и проверить на каждой системе. В Клиппере такой файл — `src/sys.zig`, и это одно из немногих мест, которые придётся переписать при переходе на новую версию Zig.
