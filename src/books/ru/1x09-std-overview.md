# Часть III. Стандартная библиотека и система

## Карта стандартной библиотеки 0.14

Стандартная библиотека Zig — исходники на Zig, лежащие рядом с компилятором (`lib/std/`). Их можно и нужно читать: документация отстаёт, а код — нет. Это первая привычка, которую стоит выработать.

### Что в ней есть для сервера

| модуль | что даёт |
| std.mem | срезы: поиск, сравнение, разбиение, сортировка |
| std.fmt | форматирование и разбор чисел |
| std.ArrayList, std.HashMap, std.StaticStringMap | контейнеры |
| std.fs | файлы и каталоги |
| std.posix, std.os.linux, std.os.windows | системные вызовы |
| std.net | адреса и простые сокеты |
| std.http | клиент и простой сервер HTTP |
| std.crypto | хеши, шифры, обмен ключами, подписи, Argon2, клиент TLS |
| std.compress | flate (deflate), gzip, zlib — сжатие и распаковка; zstd — только распаковка |
| std.unicode | UTF-8 и UTF-16 |
| std.Thread | потоки и примитивы синхронизации |
| std.testing | проверки и тестовый распределитель |
| std.Build | система сборки |

### Чего в ней нет — и что из этого следует

**Сервера TLS.** Есть клиент, нет сервера. Клиппер собрал сервер TLS 1.3 из примитивов `std.crypto`: X25519, AES-GCM, ChaCha20-Poly1305, HKDF, ECDSA и Ed25519. Это возможно именно потому, что примитивы в библиотеке есть и они хорошего качества.

**Подписи RSA.** Поэтому Клиппер не принимает ключи RSA.

**Сжатия zstd.** Только распаковка. Поэтому Клиппер сжимает deflate.

**Однобайтовых кодировок.** Таблицы кодовых страниц — данные, и библиотека их не держит.

**Асинхронного ввода-вывода.** Прежняя поддержка асинхронности в языке убрана в 0.11 и пока не вернулась. Цикл событий пишется руками поверх `epoll` или `select`.

**Базы данных, шаблонизатора, веб-каркаса.** Их нет и не будет: это не стандартная библиотека, а пакеты.

### Управляемые и неуправляемые контейнеры

В 0.14 есть два вида контейнеров. `std.ArrayList(T)` хранит распределитель внутри себя (управляемый). `std.ArrayListUnmanaged(T)` не хранит, и распределитель передаётся в каждый вызов, который может выделять память:

```
var list: std.ArrayListUnmanaged(u32) = .{};
defer list.deinit(a);
try list.append(a, 42);
```

Неуправляемый вид на одно слово меньше и, главное, по каждому вызову видно, где выделяется память. В 0.15 неуправляемый вид стал основным. Это пример того, как язык постепенно двигается к одному принципу — явности выделений — и платит за это несовместимостью.

### Вопрос: стоит ли писать своё?

Клиппер написал своё много где: HTTP, ZIP, PNG, разбор PDF, B+ дерево. Правило, к которому привёл опыт: брать из стандартной библиотеки всё, где она даёт **примитив** (хеш, шифр, сжатие, сортировка), и писать своё там, где она даёт **политику** (как разбирать запрос, как держать соединения). Примитивы трудно сделать правильно, политика — трудно сделать подходящей.
