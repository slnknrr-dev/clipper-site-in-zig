## Кодировки: байты против текста

### Вопрос: что такое длина строки?

```
const std = @import("std");

pub fn main() !void {
    const s = "Ёлка";
    std.debug.print("байтов: {d}\n", .{s.len});                         // 8
    std.debug.print("знаков: {d}\n", .{try std.unicode.utf8CountCodepoints(s)}); // 4
}
```

Исходники Zig — UTF-8, и литерал хранится в UTF-8. Кириллическая буква — два байта. `s.len` — число байтов, и другого «встроенного» понятия длины нет. Сколько в строке знаков, решает функция, и она может вернуть ошибку: байты не обязаны быть правильным UTF-8.

Это прямое следствие того, что строка в Zig — байты. Язык не притворяется, что знает, что в них.

### Обход по знакам

```
var it = (try std.unicode.Utf8View.init("Ёлка")).iterator();
while (it.nextCodepoint()) |cp| std.debug.print("U+{X:0>4}\n", .{cp});
```

`Utf8View.init` проверяет всю строку один раз; дальше обход без проверок. Это общий приём Zig: проверить на границе, дальше доверять.

### Однобайтовые кодировки

Клиппер хранит и отдаёт текст в windows-1251: один байт — одна буква. Перевод из UTF-8 — своя функция в `src/cp1251.zig`: для каждого знака найти байт в таблице из 64 значений или, если знака в кодировке нет, записать `&#N;`.

Почему не стандартная библиотека: в ней есть UTF-8, UTF-16 и ASCII, но нет однобайтовых кодировок. И это правильно: таблицы кодовых страниц — данные, а не часть языка.

### Перекодировка при компиляции

Самое интересное — где эта функция вызывается. Строки интерфейса написаны в исходниках по-русски в UTF-8, а в страницу попадают в windows-1251. Перекодировка происходит при компиляции:

```
pub fn lit(comptime utf8: []const u8) []const u8 {
    return &Converted(utf8, true).v;
}
```

`comptime utf8` — аргумент обязан быть известен при компиляции. Функция `Converted` вызывает ту же самую `encode`, что работает и при выполнении, но компилятор выполняет её сам и кладёт в программу готовые байты. В работающем сервере перекодировки строк интерфейса нет вообще. Как это устроено — глава о `comptime`.

### Где проходит граница

Правило Клиппера: внутри — одна кодировка, на границах — перекодировка. Файлы книг приходят в UTF-8 и перекодируются при разборе. Выгрузки (txt, fb2, epub) и JSON уходят в UTF-8. Адрес, набранный руками, приходит в UTF-8, и сервер это распознаёт (`looksUtf8`).

Цена однобайтовой кодировки — языки вне её. Грузинский текст в windows-1251 не помещается, и из сборки Клиппера его пришлось убрать. Язык Zig здесь ни при чём: он одинаково равнодушен к любой кодировке. Решение принимает программа.
